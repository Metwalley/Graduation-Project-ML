# دليل حل مشكلة الـ AI Engine وتكامل الباك إند (Backend Integration Guide)

هذا الدليل يوضح تفاصيل المشكلة التي كانت تواجه الـ Backend في خادم الذكاء الاصطناعي (AI Engine)، وكيف تم حلها، بالإضافة إلى شرح توضيحي لكيفية تطبيق هذه التعديلات وتأثيرها على سير العمل.

---

## ❓ السؤال الأهم: هل هذا التعديل يُلغي أي عمل تم في الـ Backend؟

**الإجابة القاطعة: لا، لا يُلغي أي شيء على الإطلاق!**

العملية هي بمثابة **Plug-Out then Plug-In Again** (فصل وتشغيل مباشر دون أي تعديل):
1. **ثبات الهيكل (API Contracts):** لم نقم بتغيير أي عنوان (Endpoint URL)، أو منفذ (Port)، أو أسماء معامِلات المدخلات والمخرجات (JSON Request/Response Schemas). كل المدخلات والمخرجات بقيت كما هي تماماً.
2. **شغل الباك إند سليم:** تطبيق Spring Boot أو أي خدمة باك إند تتصل بالسيرفر لن تحتاج إلى تعديل سطر كود واحد.
3. **التغيير الوحيد:** أن الطلبات (Requests) التي كانت تُرسل وتُرجع خطأ `500 Internal Server Error` ستُرجع الآن استجابة ناجحة `200 OK` بالبيانات المطلوبة بنسبة 100%.

---

## 🔍 سبب الخطأ بالتفصيل وكيف صلحناه

كان الخادم ينهار ويُعطي خطأ `500 Internal Server Error` عند اختبار التشخيص الأساسي لثلاثة أسباب برمجية داخل بيئة تشغيل Docker:

### 1. مشكلة تسلسل بيانات Numpy (في التوحد Autism وفرط الحركة ADHD)
- **سبب المشكلة:** نماذج الذكاء الاصطناعي (XGBoost) تُرجع قيم الاحتمال والتصنيف كأنواع بيانات تابعة لمكتبة Numpy (مثل `numpy.float32` و `numpy.int64`). في الإصدارات الحديثة من FastAPI و Pydantic، لا يستطيع المحول البرمجي تحويل هذه الأنواع تلقائياً إلى JSON، مما يؤدي لانهيار الطلب وإرجاع خطأ 500.
- **كيف صلحناه:** قمنا بعمل تحويل صريح (Explicit Casting) لجميع مخرجات النماذج الرقمية إلى أنواع بيانات بايثون الأساسية (`float(...)` و `int(...)`) قبل إرجاعها في الاستجابة.

### 2. مشكلة عدم توافق إصدار Scikit-Learn (في عسر القراءة Dyslexia)
- **سبب المشكلة:** تم حفظ نموذج عسر القراءة (`dyslexia_rf_model.joblib`) باستخدام إصدار قديم من مكتبة `scikit-learn` (إصدار 1.3.x). عند تشغيل السيرفر في Docker مع إصدار أحدث (مثل 1.6.x أو 1.7.x)، يبحث الكود الداخلي للمكتبة الحديثة عن خاصية مضافة حديثاً وهي `monotonic_cst` في أشجار القرار الفرعية، وبما أنها مفقودة في النموذج القديم، كان السيرفر ينهار تماماً بـ `AttributeError`.
- **كيف صلحناه:** قمنا بكتابة **ترقيع ديناميكي (Dynamic Hotpatch)** في كود تحميل النماذج `load_models()`. يقوم الكود تلقائياً بالمرور على أشجار نموذج عسر القراءة وإضافة الخاصية المفقودة `monotonic_cst = None` لها فور تحميلها، مما يجعل النموذج القديم متوافقاً تماماً مع أي إصدار حديث من المكتبة دون الحاجة لإعادة تدريب الموديل.

## 🚀 طريقة تحميل وتطبيق التعديلات لمهندسي الباك إند (Backend Setup)

لتطبيق التعديلات وتشغيل النظام بشكل سليم، يجب اتباع الخطوات التالية:

### الخطوة 1: تحديث الكود محلياً
قم بسحب آخر التحديثات من مستودع الـ Git (بعد أن يقوم زميلك في الـ ML بعمل Push للكود المعدل):
```bash
git pull origin master
```

### الخطوة 2: تحديث وتشغيل الـ Docker Container
أسهل وأفضل طريقة لتشغيل التحديثات وتجنب سحب الصور القديمة من Docker Hub هي **بناء الصورة محلياً واستخدامها**، أو تمرير الملف الجديد فوق الحاوية. 

إليك الخيارات المتاحة:

#### الخيار (أ) - بناء وتشغيل الصورة محلياً (الموصى به بشدة) 🌟
في ملف `docker-compose.yml` الرئيسي، بدلاً من سحب الصورة الجاهزة من Docker Hub والتي قد تكون قديمة، يفضل تعديل الخدمة لتبني الصورة من مجلد `api` المحلي.
تأكد أن خدمة `ai-engine` في ملف `docker-compose.yml` تبدو كالتالي:
```yaml
  ai-engine:
    build: ./api  # يبني الصورة محلياً باستخدام الكود المحدث
    container_name: ai-engine
    ports:
      - "8000:8000"
    environment:
      - GROQ_API_KEY=${GROQ_API_KEY}
      - GROQ_MODEL=llama-3.3-70b-versatile
      - TRACKER_JSON_PATH=/seed_data/monthly_tracker.json
    volumes:
      - ./seed_data:/seed_data:ro
    restart: unless-stopped
```
ثم قم بتشغيل الأمر التالي لإعادة البناء والتشغيل:
```bash
docker-compose up --build -d
```

#### الخيار (ب) - تشغيل السيرفر محلياً بدون Docker (للاختبار السريع)
إذا أراد مهندس الباك إند اختبار التغييرات بسرعة بدون Docker:
1. إنشاء بيئة افتراضية وتثبيت المتطلبات:
   ```bash
   cd api
   python -m venv .venv
   source .venv/bin/activate  # على Linux/Mac
   # أو
   .venv\Scripts\activate     # على Windows
   pip install -r requirements.txt
   ```
2. تشغيل السيرفر:
   ```bash
   python -m uvicorn main:app --reload --port 8000
   ```
